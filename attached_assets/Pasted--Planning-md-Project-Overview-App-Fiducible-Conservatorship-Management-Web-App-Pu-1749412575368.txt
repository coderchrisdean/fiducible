# Planning.md

## Project Overview

**App:** Fiducible – Conservatorship Management Web App **Purpose:** Track every aspect of managing a conservatorship, with daily feature rollouts.

## Core Features

1. **Landing Page**

   * Responsive hero section
   * Brief app description and call-to-action buttons (Sign Up / Login)
   * Footer with links: Privacy Policy, Terms of Service, Contact

2. **Front-End Setup**

   * **Framework:** React (via Vite or CRA)
   * **Styling:** Tailwind CSS (or your preferred utility framework)
   * **Routing:** React Router
   * **State Management:** Context API or Zustand (for global auth + settings)

3. **Back-End Setup**

   * **Runtime:** Node.js
   * **Framework:** Express.js or Next.js API Routes
   * **Authentication:**

     * Google OAuth 2.0
     * Email/Password (bcrypt + JWT)
   * **ORM:** Prisma (with PostgreSQL)
   * **Environment Variables:**

     * DATABASE\_URL
     * JWT\_SECRET
     * GOOGLE\_CLIENT\_ID & GOOGLE\_CLIENT\_SECRET

4. **Database Schema (PostgreSQL)**

   * **User** (`Conservator`)

     * id, name, email, role, passwordHash, oauthProvider, createdAt
   * **Conservatee**

     * id, conservatorId, name, dob, contactInfo, caseNumber, notes, createdAt
   * **TimeEntry**

     * id, conservatorId, date, taskDescription, memo, timeSpent (decimal hours), createdAt
   * **Additional Entities** (future features)

     * Documents, Tasks, FinancialEntries, VisitLogs, Medications, AuditLogs

5. **Authentication Flow**

   * Public routes: `/`, `/login`, `/signup`
   * Protected routes: `/dashboard`, `/time-tracking`, `/conservatees/*`
   * Session management via HTTP-only cookies or JWT in Authorization header

6. **Dashboard**

   * Summary widgets:

     * Upcoming tasks
     * Recent time entries
     * Quick-add buttons (New Time Entry, New Conservatee)
   * Navigation sidebar

7. **Time-Tracking Functionality**

   * **Create Entry**:

     * **Date Picker** component
     * **Task Description** text input
     * **Memo** textarea
     * **Time Spent** numeric input snapping to 0.1h (6-minute) increments
   * **List & Edit**:

     * Table or cards of past entries
     * Inline edit or modal
   * **Totals**:

     * Daily and weekly summaries

## Email Verification & Resend

* **Email Service:** Integrate the Resend API for sending verification and invitation emails.
* **EmailVerification** (`EmailVerification`):

  * **id**, userId, token, type (`verification` | `invitation`), caseId?, isUsed, expiresAt, createdAt
* **Flow:**

  1. On user signup, create a `verification` record and send an email via Resend.
  2. Endpoint `GET /verify-email?token=:token` marks the user as verified.
  3. **Resend** functionality: `POST /emails/resend` with email and type to resend verification or invitation emails.
* **Frontend:**

  * On signup and invitation pages, show a “Resend Email” button for unverified users or pending invitations.

## User Profiles & Roles

* **User** schema update:

  * Add `globalRole` (enum: `admin`, `user`, etc.)
* **Case** entity:

  * id, ownerId (userId), title, createdAt
* **CaseRole**:

  * id, name (e.g., `co-conservator`, `attorney`, `caregiver`, `vendor`, `auditor`, `family`), description
* **UserCaseRole**:

  * id, userId, caseId, caseRoleId, scope (enum: `read`, `write`), createdAt
* **Endpoints:**

  * `/profile` (GET/PUT) for updating user name and `globalRole`.
  * `/cases/:caseId/invitations` (POST/GET/DELETE) to manage invites.
  * `/invitations/:token/accept` (POST) for users to accept invites and create an account.
* **Frontend:**

  * **Profile Page:** allow name and globalRole updates.
  * **Case Management UI:** invite participants by email, select a case role, and send via Resend.
  * **Role-Based Views:** restrict component visibility based on `UserCaseRole.scope`.

## Daily Feature Rollout Guidelines\*\*

* **Feature Backlog**: Maintain `FEATURES.md` for upcoming items.
* **Branch Strategy**: Create a new branch per feature (e.g., `feature/time-entry`).
* **Checkpoint Frequency**: Limit to 1–2 checkpoints per feature chunk.
* **Review Process**: Use the Assistant for small tweaks; Agent only for larger implementations.

## Folder Structure

```
/src

  /pages          # Page-level views (Dashboard, Login, Signup)

/server

  /routes         # API route definitions
  /middleware     # Auth, error handling
  /config         # Env variables loader
/prisma
  schema.prisma
/public           # Static assets
```
